# PetVerse V2 非视觉功能审计

审计基线：`3d8cddcfc54cf1f0a767c13c9b355c111e7b915c`

分支：`night/core-gameplay-v2`

## 1. 结论

项目已有可复用的宠物、技能、炼妖、五宠编队、阵法、战斗、探索、好友、结婚、生蛋、孵化、背包、商店、排行和留存模块，不应推倒重写。

本轮开发应集中在：

1. 为现有炼妖测试数据和继承规则补齐验证、锁技和回归测试。
2. 新增与现有世界探索不同的轻量离线远征模块。
3. 将现有 `PetTeam.tactics` 标准化为稳定的三类战术预设接口。
4. 为五种阵法补齐可配置被动规则和战斗日志。
5. 在现有技能系统之上增加六种有循环保护的通用反应。
6. 只提供 Cocos 功能脚本、Inspector 字段和动态 Prefab，不改变用户布局。

## 2. 已完成或可直接复用

### 后端

- `Pet`：宠物个体、资质、成长、技能格、变异、特殊技能、锁定、繁育与交易状态。
- `Skill`：普通、高级、特殊技能配置，具备技能族、冲突组、继承开关和效果数据。
- `BreedingService`：使用确定性种子生成后代；支持物种二选一、技能格升降、资质和成长波动、普通/特殊技能继承与去重。
- `FusionService`：事务内扣费、生成结果宠物、消耗父母、记录结果，并使用 `requestId` 防止重复执行。
- `DevService.seedFusionPets()`：默认账号生成 PET001-PET010 的 40 只炼妖测试宠物，包含容量和资源补足逻辑。
- `PetTeam`：支持五宠、阵法、站位和 JSON 战术字段。
- `Formation`：已有五种阵法、位置加成、克制关系和阵法大招基础配置。
- `BattleV10Service`：五宠战斗会话、服务器结算、指令幂等、日志、阵法、装备、探索和爬塔接入。
- `Exploration`：已有世界章节探索、关卡、首领巢穴和结算；可与新“离线远征”并存。
- 账号、经济、背包、商店、好友、结婚、蛋、孵化、排行、邮件、成就、日常、留存、离线奖励等模块已存在。

### Cocos

- `MainUI` 已提供编辑器绑定字段，固定首页、顶部栏和底部导航以数据刷新和 `active` 切换为主。
- `PanelManager` 只切换已存在页面节点。
- 七种动态列表 Prefab 已建立：
  `PetListItem`、`InventoryItem`、`ShopItem`、`HatcheryEggItem`、`SkillSlotItem`、`FriendListItem`、`RankingListItem`。
- 固定 UI 架构审计通过 156 项检查。
- Cocos TypeScript 编译通过。

## 3. 缺失或不完整

### P0

- `server/package.json` 只有启动和构建命令，没有 lint、unit test 或 e2e 基础设施。
- 独立离线远征实体、服务和五个正式接口不存在。
- 战术仍通过 `/api/team/tactics` 的松散 JSON 更新，没有独立 options/preset 接口和稳定枚举。
- 战斗随机行为仍有 `Math.random()` 路径，无法保证同一种子完整复盘。
- 数据库使用 `synchronize: true`，没有正式迁移体系；本轮只能做向后兼容新增实体，不能宣称已具备生产迁移能力。

### P1

- 炼妖尚未公开锁定技能参数；`skill_lock` 只作为资源存在，未完整进入炼妖结果生成。
- 阵法已有大招基础字段，但缺少统一 `passiveRule`、触发原因日志和逐阵法回归测试。
- 技能配置没有标准化的战斗反应标签和六种通用反应配置。
- 新远征尚无 Cocos API、Manager、Panel 和 Inspector 数据绑定。
- 非首页页面仍有一部分旧功能在 `RuntimeContent` 中运行，不能一次性删除。

### P2

- 多个历史 TypeScript 文件中的中文文案存在明显乱码。它不阻塞英文接口和结构开发，但会影响页面文案、日志与最终发布品质。
- Cocos 本机设置文件有未提交修改，属于编辑器环境状态，不纳入功能提交。
- 本机缺少 GitHub CLI，因此可以完成本地分支和分阶段提交，但暂时不能按标准插件流程推送并创建草稿 PR。

## 4. UI 运行时风险

前端仍存在动态节点调用，但需要区分用途：

- 固定 UI：不得创建、销毁、清空或修改 Transform。
- 动态列表、Toast、战斗表现、加载遮罩：允许按功能实例化。
- `RuntimeContent` 是当前旧功能隔离层，在对应页面迁移并验证之前不得删除。
- 页面迁移必须逐页进行，每页单独提交；用户视觉布局不在本轮修改范围内。

## 5. 兼容策略

1. 新远征使用独立 `expedition_*` 数据，不复用或改写世界探索进度。
2. 战术预设继续保存在 `PetTeam.tactics`，通过规范化适配旧字段，避免数据库破坏性修改。
3. 阵法配置扩展现有对象，不改变旧 `formationCode` 和站位数据。
4. 技能反应通过标签和通用规则叠加，不批量重写现有技能。
5. Cocos 新功能先提供可选绑定；未绑定节点只警告，不阻塞首页。

## 6. 本轮不处理

- 不改首页或任何页面的视觉位置、尺寸、锚点、字体、图片、颜色和层级。
- 不制作复杂远征故事树、性格、默契、家族或宠物 AI。
- 不重写战斗、炼妖、结婚或孵化系统。
- 不删除旧资源、旧 RuntimeContent、数据库表或用户数据。
- 不把历史乱码修复与功能改动混成一次大范围机械替换。
