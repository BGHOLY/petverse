# PetVerse 留存系统审计

审计基线：`ui-redesign-v2` / `5e3813a944b4639413a85fce166daf5d1db4089a`

## 已有并继续复用

- `SignModule`：已有单日签到、连续与累计签到字段、首页福利页入口。
- `DailyTaskModule`：已有签到、喂养、爬塔、战斗四个布尔任务及总奖励。
- `AchievementModule`：已有签到、爬塔、宠物、好友、繁育、炼妖等历史数据补算。
- `RankingModule`：已有宠物等级/战力、爬塔、赛季榜。
- `MailModule`：已有多附件、已读、单领/一键领取、过期时间与请求幂等。
- `EconomyModule`：已有事务内钱包和物品增减、操作请求记录。
- 首页四个入口已经存在：七日签到、萌新礼包、每日任务、精彩活动。
- 福利、排行和邮件页面已有绘本 UI 基础，不重新设计整体结构。

## 已有实现的主要缺口

- 签到与每日任务分别直接发奖，缺少全局统一奖励领取记录。
- 签到按客户端/进程本地自然日判断，没有统一的 05:00 服务器日界线。
- 每日任务只有四个布尔值，不能支持计数任务、周任务、单项领取和一键领取。
- 萌新礼包与活动入口只有页面跳转映射，没有真实进度和领取数据。
- 红点由客户端分别计算，不能给出统一来源与总数。
- 排行榜缺少玩家等级、五宠总战力、探索度、首领通关和“我的排名”。
- 成就配置数量少且只有单档，不含完整分类和阶段。
- 邮件发奖仍依赖旧经济操作记录，没有共享其他奖励来源的统一业务幂等键。

## 本阶段统一约定

- 服务器时区：`Asia/Shanghai`（UTC+8）。
- 每日重置：05:00；周重置：周一 05:00。
- 所有领取通过 `RewardService`，以 `userId + businessType + businessId` 唯一。
- 奖励领取和业务状态写入同一数据库事务，任一步失败全部回滚。
- 客户端只展示服务端状态，不能自行增加货币、背包、宠物经验、装备或宠物蛋。
- Cocos 继续复用现有首页入口、福利页、排行榜和邮件页；不改冻结页面与底部导航。
